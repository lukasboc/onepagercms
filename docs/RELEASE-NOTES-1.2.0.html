Release Notes — v1.2.0

Extensions, Themes & Marketplace Update

Highlights

Version 1.2.0 is the biggest OnePagerCMS release so far. The CMS is now extendable: you can install plugins and themes — either directly from the new marketplace inside the admin backend or by uploading a ZIP file. On top of that, the complete admin backend has been redesigned.

  • New plugin system with a WordPress-style hooks API
  • New theme system — change the entire look of your one-pager without touching core files
  • Built-in marketplace — browse, install and update extensions with one click
  • Completely redesigned admin backend
  • Improved update.php with a visual migration report

New: Plugins

Plugins live in the new extensions/ directory and are managed on the new Extensions page in the admin backend (Installed / Marketplace / Upload tabs). Each plugin ships a plugin.json manifest and a main entry file.

  • Hooks API: plugins register into the CMS via add_action() and add_filter() — the same mental model you know from WordPress.
  • Custom section types: plugins can register entirely new section types via opcms_register_section_type(). They appear in the normal "New Section" dialog next to Standard, Icons and Contact and integrate with section ordering and deletion.
  • Plugin admin pages: plugins can add their own settings pages to the admin backend.
  • Safe installation: ZIP uploads are validated and protected against path traversal (zip-slip). Plugins can declare a minimum CMS version via requires_opcms.

New: Themes

The frontend rendering has been moved into a template-based theme engine. Themes live in the new themes/ directory and are activated on the Design page.

  • The bundled default theme Agency reproduces the previous frontend output exactly — after updating, your website looks the same as before.
  • Themes bring their own templates for the index page, additional pages, header, footer, navigation and every section type. A theme can also override how plugin sections are rendered.
  • Theme options: themes can define their own settings (colors, layout options, …), which show up automatically on the Design page.
  • Themes can be installed from the marketplace or via ZIP upload, just like plugins.

New: Marketplace

The Extensions page contains a Marketplace tab that lists available plugins and themes directly inside the admin backend.

  • One-click install and update of extensions
  • Update notifications for installed extensions
  • Paid extensions: OnePagerCMS itself stays 100% free and contains no payment code. For paid third-party extensions you enter a license key in the backend; downloads and updates are then delivered through the developer's own update endpoint.

Redesigned Admin Backend

Every backend page — login, sections, design, settings, account, FAQ, additional pages and the new extensions area — has been rebuilt with a modern, responsive UI (Tailwind CSS 4 + DaisyUI). Functionality and URLs are unchanged; everything is just cleaner and faster to use.

  • Consistent navigation with a corrected menu order
  • Faster logout
  • The stylesheet is pre-built and shipped as css/admin.css — end users do not need Node.js or any build step.

Improvements & Bug Fixes

  • E-mails: the contact form and account e-mails now send an RFC 2822-compliant From: header (noreply@your-domain) plus a Reply-To: header with the sender's address. Previously, strict mail servers rejected these e-mails.
  • FAQ: new installations now ship with a set of default FAQ entries including categories; existing installations receive the updated defaults through update.php.
  • Security: all new action handlers (extensions, themes, marketplace) verify the admin session before doing anything.
  • Smaller download: vendored library source trees (Trumbowyg sources, duplicated Bootstrap/jQuery copies under pages/vendor/) were removed — only the required distribution files ship with the CMS.
  • Fixed missing icons on some backend pages.

For Developers

Want to build your own plugin or theme? The full developer documentation lives in the repository at docs/EXTENSIONS.md and covers the hooks API, the plugin.json / theme.json manifests, custom section types, theme templates, theme options and the update/license protocol for paid extensions.

Database Migration Required

Existing installations must run update.php once after uploading the new files. The script is idempotent — it detects what your database is missing and only applies those changes. It works for updates from v1.0.x as well as from v1.1.0. No content is deleted or changed.

Fresh installations don't need update.php — the database is created automatically with the current schema on first access. Just follow the normal installation instructions and delete update.php from your webspace afterwards.

How to update — v1.2.0

Before you start: Save your database!

yourOpcmsInstallation / database / SQLiteDatabase.db

Copy this file to your computer before doing anything else.

Steps (from v1.0.x or v1.1.0)

  1. Save your database — copy database/SQLiteDatabase.db to your computer.
  2. Download v1.2.0 from onepagercms.de. The "Download" button always links to the latest version.
  3. Upload the new files to your webspace — just like during the initial installation. Override all existing files.
  4. Restore your database — upload the SQLiteDatabase.db you saved in step 1 back into the database/ folder and override the file that came with the download.
  5. Run the update script — open the following URL in your browser:
https://your-domain.de/update.php

The script now shows a detailed report of every migration (executed / skipped / error) and creates a lock file (.update.lock) so it cannot run twice by accident.

Delete update.php from your webspace once the script has finished successfully.

Coming from v1.0.x?

The same steps apply — no extra work needed. update.php automatically includes all v1.1.0 migrations (renamed section columns, section positions, background images, header/footer tables, FAQ categories, additional pages, and more) and applies whichever ones your database is still missing.

Note for v1.0.x users — FAQ categories:
If you use FAQ sections with categories, re-open each FAQ entry in the admin and save it once. Due to a bug in v1.0.x, the category field was accepted but never stored — this has been fixed in v1.1.0.
Note on extensions:
The new plugin, theme and marketplace features require no manual migration. The extensions database table is created automatically the first time you open the Extensions page. After the update, the bundled Agency theme renders your website exactly as before — nothing changes on your live site until you actively install or activate something new.
