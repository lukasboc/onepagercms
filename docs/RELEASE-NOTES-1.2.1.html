Release Notes — v1.2.1

Spam Protection Update

Highlights

Version 1.2.1 replaces the contact form's captcha with a built-in, invisible spam protection — no configuration, no external services, no puzzle for your visitors. It works out of the box and is GDPR-friendly: no visitor data is sent to third parties and no cookie consent is required.

  • Invisible honeypot field that traps form-filling bots
  • Signed form tokens — bots posting directly to the form handler are blocked entirely
  • Time trap — submissions faster than a human could type are rejected
  • Rate limiting — at most 3 messages per 10 minutes per visitor
  • Strict server-side validation of every submission
  • Google reCAPTCHA has been removed

New: Invisible Spam Protection

Previously, the contact form's only defense was an optional Google reCAPTCHA — and its server-side check was broken, so bots could flood your inbox by posting directly to the form handler. v1.2.1 closes this completely with four layers that are invisible to real visitors:

  • Signed form token: every contact form embeds a cryptographically signed token bound to the form and the time it was rendered. Requests without a valid token — i.e. every bot that posts directly to the handler — are dropped without sending a mail.
  • Honeypot: an invisible extra field that humans never see. If it is filled in, the sender was a bot and the message is discarded.
  • Time trap: submissions arriving less than 3 seconds after the page was rendered are treated as bots. Forms older than 24 hours ask the visitor to reload the page.
  • Rate limiting: a maximum of 3 messages per 10 minutes per visitor — even a bot with a valid browser session can no longer flood your inbox.

Blocked bots are shown a normal "message sent" page so they don't learn how to adapt; real visitors who hit the rate limit or a validation error see a clear message explaining what to do.

GDPR / Privacy

  • No external services: the Google reCAPTCHA integration (including its script embed) has been removed. Your one-pager no longer loads anything from Google for the contact form, so no consent banner is needed for it.
  • No plain-text IP storage: the rate limiter never stores visitor IP addresses. It only keeps a keyed hash (HMAC with a secret generated on your own server), and entries are deleted automatically after one hour.

Security & Bug Fixes

  • Mail header injection fixed: the contact form's Reply-To header is now built only from a validated e-mail address; line breaks are stripped. (This also fixes a bug where Reply-To was never set at all — replying to contact messages now works.)
  • Unauthenticated settings endpoint removed: misc/changecaptcha.php accepted requests without an admin session. The file has been deleted along with the reCAPTCHA feature.
  • Strict server-side validation: the handler now validates required fields, e-mail format and input lengths, and the notification mail contains only the actual form fields (Name, Mail, Message) instead of the raw request data.
  • The success and error pages for the contact form now always show a proper headline and message (previously they could be blank).

For Theme Developers

If your theme overrides the section-contact template, it must render the new protection fields inside the form — otherwise submissions will be silently dropped by the handler. It is two lines of code; see the "Contact form spam protection" section in docs/EXTENSIONS.md and the reference implementation in themes/agency/templates/section-contact.php. Themes using the documented class_exists() guard remain compatible with older CMS versions.

How to update — v1.2.1

No database migration is required. Everything the new spam protection needs (its table, its secret key and its status messages) is created automatically on first use.

  1. Save your database — copy database/SQLiteDatabase.db to your computer.
  2. Download v1.2.1 from onepagercms.de.
  3. Upload the new files to your webspace and override all existing files. Then delete misc/changecaptcha.php from your webspace if it is still there.
  4. Restore your database — upload the SQLiteDatabase.db you saved in step 1 back into the database/ folder.

Updating from v1.1.0 or older? Run update.php once after uploading (and delete it afterwards), exactly as described in the v1.2.0 release notes — it applies all missing migrations up to the current version.

Note on the Captcha setting:
The reCAPTCHA option has been removed from the settings page and from the Contact section editor. Existing contact sections keep working unchanged — the captcha checkbox and API key are simply ignored. You can delete your reCAPTCHA API key in your Google account; the CMS no longer uses it.
